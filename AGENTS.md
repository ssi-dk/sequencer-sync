# Sequencer-sync
This file provides guidelines for agents working with this codebase.

This is a Rust binary with a CLI interface which runs on DNA sequencer machines, and which is responsible for copying files from sequencing runs.
It copies a subset of files from the "source" directory, where files from complete sequencing runs are found, to a "landing zone".
Each category in the config declares its own landing zone, which is either a local directory on the sequencer (`kind: local`) or an SSH-reachable directory on a remote host (`kind: remote`, with `user`/`host`/`port`/`dir`). Local landing zones are typically followed by a separate program copying onto a remote server; remote landing zones deliver directly via rsync over SSH.

Subcommands:

* `sequencer-sync setup`:
	- Validates config file (local landing zones must exist on this machine and are canonicalized; remote landing zones are taken as-is)
	- Checks `source`, `flockdir`, `logdir` and every local landing zone for the right permissions
	- For each remote landing zone: a single SSH probe verifies passwordless SSH access and that the remote `dir` exists and is writable. Skipped with `--skip-ssh-check`.
	- Generates a cron file for scheduling `run`. User must schedule
      the cron job to run `run` themselves.
  Setup should be idempotent.
  Purpose is to set up new sequencer. Need only be run once every time software is updated, if successful.
* `sequencer-sync run`:
    - Loads and validates config file
    - Loads the transfer log (JSONL) with previous transfers
    - Checks for directories in source dir not in transfer log
    - Transfers those to the matched category's landing zone using rsync. For remote landing zones rsync runs over SSH (`-e 'ssh -p <port> -o BatchMode=yes'`) with destination `user@host:/dir/`.
    - Records transfer in JSONL log (authoritative), then best-effort writes to
      the human-readable run log and the transfer marker file (`touch` over SSH for remote landing zones).
  Invoked by cron job generated by `setup`

## Testing

* `cargo test` runs all unit and integration tests against local landing zones.
* The remote/SSH path has both unit coverage (`build_rsync_argv` tested for both variants in `src/main.rs`) and an opt-in end-to-end test in `tests/integration.rs` (`remote_e2e::rsync_over_ssh_to_localhost`) gated by `SEQUENCER_SYNC_E2E_REMOTE=1`. The e2e test starts a private sshd in a temp dir on a high port and uses an `ssh` shim on `PATH` so the test never touches the user's real `~/.ssh`. It requires `sshd`, `ssh-keygen`, and `ssh-keyscan` to be installed.

## Coding guidelines
* Do not put yourself as git co-author
* Run `cargo clippy` after each round of changes and address lints, then run `cargo fmt`.
* This program runs on a sequencer and in the background so runtime crashes are inconvenient.
  Make an extra effort to avoid possible but unlikely sources of errors, and lean on the type system
  to statically avoid bugs.
